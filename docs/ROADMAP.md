## Maintenance décidée (audit v0.14.1)

À faire, chacune dans une session dédiée :

- **electron-builder** (outil de fabrication de l'installateur, rien d'embarqué dans l'app ; 26.15.3 installé, 26.18 disponible) : les vulnérabilités « modérées » signalées en v0.14.1 ont disparu de `npm audit` (0 en v0.19.0, après correctifs des dépendances transitives) ; la mise à jour reste à faire dans une session dédiée, avec un test d'installation du `.exe` sur Windows.
- **Versions majeures**, une à la fois, avec rendus de référence et captures avant / après : Electron 45, react-router 8, TypeScript 7 (quand typescript-eslint le prendra en charge), `@types/node` 26 ; aussi `@napi-rs/canvas` 1.0.13 (rendu des Reels), polices `@fontsource` 5.3 et `lucide-react` 1.61 (interface).

Proposé par l'audit v0.19.0 (à décider, une session chacun ; détail dans `docs/rapports/2026-10-24-v0.19.0.md`) :

- Décodage et analyse audio communs (moteur vidéo, Pack Insta, Analyse du master) dans le SDK.
- Composants de graphes communs (Stats YouTube, Analyse du master) dans le SDK.
- Guide intégré pour les autres modules complexes (Stats YouTube, Assistant, Reels perso).
- Zone de notification : une API générique du socle pour y afficher un court état (ex. temps restant du Timer) ; aujourd'hui seul l'indicateur flottant est utilisé.

Écarté (gain trop faible pour le risque) :

- Aide partagée pour le sujet `music-library:track:<id>` : format stable et documenté ; la factoriser demanderait un import d'exécution entre modules ou un changement du service `musicLibrary`.
- Analyse audio du Pack Insta sur le décodage du moteur : le choix des extraits proposés pourrait changer.
- Réenregistrement des fichiers au démarrage (`created_at` réécrit à ±1 ms, compteur d'identifiants qui avance) : aucun effet visible, toucher au registre des fichiers serait plus risqué que le défaut.

## Plus tard (hors V1, la structure doit le permettre)

- **Version Android synchronisée** avec le PC sur le réseau local : les nouveaux modules sont déjà « Prêts pour la synchro » (UUID, dates, suppressions logiques, journal `<module>__changes`, MODULES.md §6 bis) ; les modules existants seront adaptés dans une session dédiée.
- **Calendrier général** : interroge toutes les sources `ctx.calendar` (`GET /api/core/calendar`, MODULES.md §5.17). Déjà branchés : Sport, Courses. À brancher : Planning de sortie, To-do (échéances), Timer (sessions).
- **Sport** : exercices et tags par séance, statistiques par type de séance.

- **Assistant vocal V2** :
  - mot de réveil (« Hé ToolBox », détection locale, sans touche) ;
  - recherche Internet (facultative, toujours annoncée comme telle) ;
  - briefing du matin (tâches du jour, publications, stats de la veille, lu à l'ouverture) ;
  - cerveau interchangeable (autre moteur local qu'Ollama, ex. llama.cpp embarqué).
  - Aussi : actions de modification dans les autres modules (cocher « Publié »…), annuler pendant la réflexion, choix du micro.
- **To-do** : répétition (chaque lundi…), rappels Windows à l'échéance, sous-tâches, priorité.

- **Instagram — Stories** : format 9:16 dédié dans le pack (extrait court + autocollant de lien), à côté des Reels et du post.
- **Instagram — publication directe** du pack via l'API Instagram de Meta (compte Créateur/Professionnel + app Meta développeur), avec programmation : le Planning de sortie l'utiliserait à la place des rappels ; la case « Publié » serait alors cochée automatiquement. - **SoundCloud** : stats via l'API officielle (abonnement Artist Pro requis pour obtenir des identifiants). Futur module `soundcloud-stats`.
- **Tableau de bord unifié** multi-plateformes par morceau.
- **Variantes de mise en page** (toujours conformes à `docs/DIRECTION-ARTISTIQUE.md` : cover entière, mouvements lents, couleurs de la cover), au choix par morceau.

- Planning de sortie : choix de la playlist par morceau ; modification du titre/description d'une vidéo déjà envoyée (aujourd'hui : dans YouTube Studio).
