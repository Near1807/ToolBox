# Rapport de session — v0.29.1 (05/11/2026)

Session « Version téléphone, étape 2 : cœur partagé sur le PC (zéro changement de comportement) ».

## 1. Résumé

- Le code des 5 modules du téléphone (Courses, Sport, To-do, Timer, Boîte à idées) n'importe plus rien du PC : SDK portable `@hub/sdk/core`, images et fichiers par `ctx`, `crypto.randomUUID`. Une règle ESLint le garantit.
- Le client d'API des pages a un transport injectable ; le transport HTTP du PC est celui d'avant.
- **Références de non-régression** écrites par la v0.29.0 avant tout changement : elles passent à l'identique après le portage (Courses, Sport, To-do, Timer, Idées, images).
- ADR 0044 **acceptée**. Version 0.29.1 : réorganisation interne, rien de visible.
- Suite rapide verte, lint et typecheck verts, essai de l'app réelle concluant. CI Windows (suite complète, build, `.exe`) **verte**. Sur ton PC : **non testé en réel**.

**Ce que l'étape 3 pourra brancher**

1. **Hôte téléphone** (Worker) : construire un `ModuleContext` avec la même interface (`db`, `routes` en mini routeur qui appelle les handlers avec `{ params, query, body, raw }`, `settings`, `services`, `calendar`, `notifications`, `files`, `images`, `assistant` sans effet), puis appeler `register(ctx)` des 5 modules.
2. **Adaptateur sqlite-wasm** : un objet `ModuleDatabase` (`prepare` → `run` / `get` / `all`, `transaction`, `table`) au-dessus de `@sqlite.org/sqlite-wasm` (OPFS), synchrone dans le Worker ; les migrations des modules tournent telles quelles.
3. **Transport Worker** : un `ApiTransport` (`request` → message au Worker, réponse en `Response` ; `openEventStream` → abonnement), donné à `setApiTransport` au démarrage. Les écrans ne changent pas.
4. **Fichiers et images** côté téléphone : `ctx.files` sur OPFS (accès synchrone dans le Worker) et `ctx.images.normalise` par `OffscreenCanvas` ; les empreintes du téléphone pourront différer de celles du PC (autre encodeur JPEG), d'où l'envoi des images par empreinte décidé dans l'ADR.

## 3. Pas fait ou en partie

- **Flux d'événements dans les références** : `/events` du Timer n'est pas dans la référence (le test d'injection ne garde pas une connexion SSE ouverte). Il est vérifié dans l'app réelle (§7) et par le test du transport.
- **Modèle de module** (`modules/_template`) : il importe encore `node:fs` et `@hub/sdk/backend` (il n'est pas du téléphone). À décider si les nouveaux modules doivent partir de `core`.
- Les globaux Node (`Buffer`, `process`) ne sont pas interdits par ESLint dans les 5 modules ; aucun n'en utilise (vérifié par recherche).

## 4. Décisions prises sans Thomas

1. **Images** : le socle reçoit les paramètres (`maxSide`, `quality`, `maxBytes`, `background`) ; les valeurs restent dans le module Courses. Le message « Image trop lourde (20 Mo au plus) » est calculé depuis `maxBytes` (même texte).
2. **Fichiers** : `writeFile` et `removeFile` refusent tout chemin hors du dossier de données du module (vérification ajoutée, aucun effet sur les chemins actuels) ; `readFile` accepte un chemin choisi par l'utilisateur, comme avant.
3. **`openEventStream`** reste dans `core`, typé sur des interfaces minimales : le Worker pourra fournir de faux `request.raw` / `reply.raw`.
4. **`precheckTrack`** (musique) reste dans `core` : il n'importe rien du PC.
5. **Règle ESLint** : liste étendue aux natifs du PC (`ffmpeg-static`, `uiohook-napi`…) au-delà de la liste demandée.
6. **Référence des images** : l'empreinte des images d'**entrée** (dessinées par le test) est retirée, voir §6.

## 9. Risques et points à surveiller

- **Encodeurs d'image** : les octets JPEG sont identiques entre Linux et Windows avec la même version de `@napi-rs/canvas`. Une mise à jour de cette dépendance peut les changer : la référence des images le dira.
- **Contrat élargi** : `ctx.images` et les nouvelles méthodes de `ctx.files` devront être fournies à l'identique par l'hôte téléphone.
- `@hub/sdk/backend` réexporte tout `core` : rien n'empêche un module de musique de garder ses imports, c'est voulu.
