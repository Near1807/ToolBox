# Coffre — cahier des charges

> Référence des sessions du module « Coffre ». **Réécrit en v0.50.0** : le modèle « tout est dossier » remplace celui des v0.45–v0.49. Pourquoi, et ce que l'ancien modèle contenait : ADR 0067.
> Chaque point porte sa version. Ce qui change ici change dans le même commit que le code.

## But

UN endroit pour **garder, ranger, retrouver et ouvrir** tous les fichiers qui comptent pour Thomas : supports de cours, synthèses, code, rapports, contrats, fichiers d'applications.

Le rangement est **l'arborescence classique de Windows** : des dossiers dans des dossiers, des fichiers dedans. La nouveauté du Coffre est dans **l'accès** : la carte, la recherche (noms, étiquettes, contenu), les étiquettes, les aperçus, la sauvegarde sur un disque externe.

Outil **PC seulement**. Rien en ligne, rien envoyé à l'extérieur. Interface « atelier » par les jetons du thème et les composants du SDK, lisible en thème clair et sombre.

## Vocabulaire

Un mot par notion, partout : interface, documentation, et autant que possible le code (en anglais entre parenthèses).

## Règles

1. **Déductions** — toute étiquette ou route devinée reste modifiable ; une étiquette **choisie** n'est jamais remplacée ensuite par une déduction ; sans indice, rien n'est proposé. Les corrections servent à mieux proposer (apprentissage, ADR 0061), jamais à la place d'un « choisi ».
2. **Le Coffre est lisible sans ToolBox** — le chemin d'un fichier est sa route (`Cours/Thermo/fichier.pdf`), sur le PC comme sur le disque. Les étiquettes ne sont **pas** dans le chemin : en changer ne déplace rien. Noms toujours valides sous Windows ; jamais d'écrasement (« nom (2) »).
3. **Rien n'est supprimé sans confirmation** — supprimer = corbeille du Coffre (avec « Annuler »), puis corbeille du disque ; l'effacement définitif est à part, confirmé, jamais automatique.
4. **Ouvrir** — ce qu'un lecteur sait afficher s'affiche dans ToolBox ; le reste s'ouvre dans son application sur demande. Un exécutable ou un script n'est **jamais** lancé sans une confirmation qui le nomme (le socle le vérifie aussi) ; un fichier de code s'ouvre dans VS Code ou l'aperçu, jamais dans son application (v0.47.1).
5. **HTML** — affiché isolé : ni réseau, ni fichiers, ni script.
6. **L'original n'est jamais touché** — le Coffre copie.
7. **La désinstallation n'efface jamais le dossier de données** (Coffre compris).
8. **Disque** (v0.46, inchangé ; ADR 0055) — identité (jamais la lettre), mise à jour **par un clic** (plan, place vérifiée, copies sous un nom temporaire relues puis mises en place, annulable, cohérent après un débranchement), archiver / réactiver après copie relue, historique avec quota en Go, corbeille du disque jamais vidée seule, restaurer depuis un disque, vérifier. Le dossier du disque **suit les routes** (un dossier déplacé ou renommé y est déplacé, rien n'est recopié).
9. **Tâches de fond** (v0.49, ADR 0066) — tout geste qui peut durer plus d'une seconde est une tâche suivie (progression, Annuler, erreurs une à une et « Réessayer », reprise au redémarrage pour un dépôt).

## Le modèle — v0.50 (livré, Expérimental)

### Carte, arbre, vues

1. **Carte et arbre** : uniquement les dossiers ; jamais de fichiers ni de dossiers cachés ; arrêtés sur les fins de route et les projets (un nœud avec son badge) ; À ranger en haut avec son compteur ; un clic y va directement. Gestes : déplacer par glisser (confirmé), fusionner, renommer, supprimer s'il est vide, réordonner, « Annuler ». Les nombres comptent les fichiers (hors exclus) du dossier et de ses descendants.
2. **Vue d'un dossier** : sous-dossiers et fichiers, en cartes ou en liste (choix retenu) ; filtres par étiquette (pastilles par famille) ; déposer ici ; « Nouveau dossier », « Nouveau fichier… ». En-tête : nom, route, nombre de fichiers, état du disque, badges, étiquettes par défaut.
3. **Vue d'une fin de route ou d'un projet** : arborescence intérieure à gauche (sans dossiers cachés, sauf case), le fichier choisi affiché à droite par son **lecteur** ; le README par défaut, sinon la liste des fichiers en cartes ; clavier ↑ ↓ → ← Entrée ; Ctrl+P cherche un fichier par son nom dans ce dossier. On y **entre** toujours dans ToolBox ; VS Code ou l'application seulement sur demande. Un projet montre en plus sa branche et son dernier commit.
4. **Recherche** (Coffre et Ctrl+K) : par nom, étiquette et contenu des fichiers rangés ; vues par étiquette (« tout ce qui est Python »).

### Gestes

1. **Déposer des fichiers** : fenêtre de rangement avec route (sélecteur de route) et étiquettes proposées, dont les étiquettes par défaut du dossier visé ; « Pour tous » pour un lot ; « Ranger plus tard » → À ranger. Tâche de fond, copie, original en place (chemin et empreinte retenus).
2. **Déposer un dossier** : il arrive **tel quel**, avec toute son arborescence, à la route choisie ; jamais découpé. Ses sous-dossiers qui ressemblent à des projets reçoivent le badge Projet **proposé** (visible et modifiable dans l'aperçu, qui montre aussi nombres, tailles, doublons, exclus et seuil pour les gros dossiers).
3. **Créer** : « Nouveau dossier » et « Nouveau fichier… » partout (vue d'un dossier ou d'un projet, clic droit, bouton) ; un fichier est créé **vide** avec le nom et l'extension tapés, nom Windows valide, jamais d'écrasement ; puis ToolBox propose de l'ouvrir (code → VS Code, autre → son application ; aucun exécutable lancé sans confirmation).
4. **Étiquettes** :
   - « Copier les étiquettes » d'un fichier (Ctrl+Maj+C) et « Coller les étiquettes » sur un ou plusieurs fichiers (Ctrl+Maj+V), en choisissant **Ajouter** ou **Remplacer** ; Annuler ;
   - **étiquettes par défaut d'un dossier**, réglées dans son en-tête : proposées d'office (« par défaut du dossier ») aux fichiers déposés ou créés dans ce dossier et ses sous-dossiers, sauf si un sous-dossier a les siennes (la plus proche l'emporte) ; jamais appliquées aux fichiers déjà présents sans clic (« Appliquer aux fichiers déjà présents », aperçu, Annuler) ;
   - **ensembles d'étiquettes** nommés (« Slides de cours ») : créés depuis un fichier ou un dossier, réutilisés en un clic (fenêtre de rangement, « Pour tous », coller, étiquettes par défaut), renommés, supprimés.
5. **Déplacer / renommer un dossier** : tout son contenu suit (PC tout de suite, disque à la prochaine mise à jour, par déplacements) ; Annuler ; un projet se déplace entier.
6. **Poser / enlever Fin de route ou Projet** : seule la carte change (et, pour Projet, les comportements du code) ; aucun fichier ne bouge sur le PC ; Annuler.
7. **Modifier un fichier dans son application** : vu par le Coffre → « pas encore sur le disque ».
8. **Archiver / réactiver** : un fichier ou un dossier ; un projet toujours entier.
9. **Supprimer** : corbeille du Coffre, puis corbeille du disque ; rien d'effacé sans confirmation ; un projet entier.
10. **Mettre à jour le disque** : un clic, plan, copies relues ; le dossier du disque suit les routes.

## Projets avancés — v0.51 (livré, Expérimental ; ADR 0068)

1. **Fichiers intérieurs d'un projet** : un index par projet (chemin, nom, type, taille, date, empreinte), hors exclus, construit en tâche de fond au rangement, mis à jour au démarrage, au regard périodique et avant une mise à jour du disque ; seuls les fichiers changés sont relus. Dans la recherche (Coffre et Ctrl+K), chaque fichier intérieur est un résultat : par **nom** et par **contenu** (« main.py — Cours › GPU › Labos (projet) », extrait, ligne ou page). L'ouvrir ouvre **ce** fichier : vue du projet positionnée dessus (lecteur à sa ligne ou sa page), plein écran, ou VS Code sur le projet à la ligne. Dans les vues par étiquette, les fichiers intérieurs apparaissent **groupés par projet** (langage par l'extension, année par la date, le reste du projet). Un fichier intérieur **n'a pas de fiche** : le projet reste l'unité d'étiquetage (dit dans l'interface).
2. **Disque fichier par fichier** : un **manifeste** par projet (sur le PC, et lisible sur le disque dans `_ToolBox/Base/projets/`). Une mise à jour ne copie que les fichiers **ajoutés ou modifiés** ; un fichier remplacé, supprimé ou renommé garde son ancienne version dans l'historique. Un projet n'est « à jour » que si **tous** ses fichiers correspondent ; interrompue, la mise à jour le laisse « pas encore sur le disque » et la suivante termine (même copie sûre). Les projets copiés entiers en v0.50 passent au manifeste **sans recopie** (empreintes comparées). Le plan dit « n fichiers à copier ».
3. **Historique par fichier** : « Versions » sur un fichier d'un projet ; « Restaurer cette version » (l'actuelle gardée d'abord dans l'historique ; confirmation ; Annuler). Quota inchangé (jamais les fichiers actuels ni les archives).
4. **Exclusions** d'un projet : liste par défaut + ce que disent ses `.gitignore` (racine et sous-dossiers, syntaxe complète) + les choix de Thomas (« Ne pas sauvegarder ce dossier » / « Le sauvegarder quand même », qui l'emporte), lisibles et modifiables dans la vue du projet, avec la place gagnée. `.git` jamais exclu. Exclu = ni sauvegardé, ni recopié sur le disque, ni cherché, ni indexé ; grisé « non sauvegardé, recréable » (ou sa raison) quand les dossiers cachés sont affichés ; exclure ne touche jamais aux fichiers. Ce que liste un `.gitignore` est quand même copié dans le Coffre au rangement (rien n'est perdu) ; archiver un projet qui a de tels fichiers est refusé, dit. Une copie du disque qui contient ce qui n'est plus sauvegardé : **proposé** (un clic, place gagnée) de le retirer vers l'historique du disque ; jamais seul.
5. **Git, sans risque** : jamais de copie pendant que Git écrit (`.git/index.lock` ou un autre `.lock`) : reporté à la fin, réessayé, sinon « pas encore sur le disque » avec la raison. Lecture seule : branche, dernier commit, modifications non commitées (lues dans l'index de git ; sinon rien). Aucune commande git.
6. **Projet suivi en place** : au rangement d'un dossier qui est ou contient un projet, « Copier dans le Coffre » (défaut) / « Laisser en place et le suivre » (pour les projets qui doivent garder leur chemin, ex. un lanceur), aussi par projet dans l'aperçu d'un gros dossier. Un projet suivi : visible à sa route (badge « Suivi en place » + chemin réel), cherché et indexé, sauvegardé sur le disque comme les autres (sa place sur le disque suit sa route) ; sur le PC il ne bouge **jamais** (changer sa route, déplacer son dossier parent : seul son rattachement change). Jamais archivé (dit) ; « Retirer du Coffre » arrête le suivi (sa copie du disque va dans la corbeille du disque), son dossier reste intact. Introuvable (renommé, déplacé, autre disque) : « introuvable », jamais oublié ; « Le retrouver… » (le nouveau dossier, vérifié par ses fichiers) ; la copie du disque reste intacte. Modifications faites sur place : vues au regard. Conversions : copié → suivi (le Coffre le copie dans un dossier vide, ou un dossier qui le contient déjà est comparé, différences montrées avant tout choix ; la copie du Coffre part dans son dossier `_Corbeille` seulement après succès ; Annuler) ; suivi → copié (copie dans le Coffre, l'original reste intact et n'est plus suivi, dit).
