## Vocabulaire (interface, docs, cahier des charges)

- DOSSIER : une boîte, comme sous Windows ; un dossier dans un dossier = une ROUTE. Le mot « contexte » disparaît de l'interface et de la documentation (les noms internes du code et des tables peuvent rester ; le dire dans l'ADR).
- FICHIER : un fichier, dans un dossier.
- PROJET : un BADGE sur un dossier, qui en fait une FIN DE ROUTE (boîte fermée) : ses sous-dossiers ne sont jamais des branches de la carte ni de l'arbre ; il forme une unité indivisible (E). Interrupteur visible, proposé automatiquement avec sa raison, modifiable à tout moment, sans déplacer aucun fichier.
- DOSSIER CACHÉ : nom commençant par un point (.git, .vscode, .idea…) ou dossier recréable (node_modules, .venv, venv, `__pycache__`, .pytest_cache, .mypy_cache, .pio, .gradle, .next, .nuxt, .cache ; et dans un projet seulement : build, dist, bin, obj, out, target) ou ignoré par un .gitignore. Caché partout par défaut ; case « Afficher les dossiers cachés ».
- EXCLU : ce qui n'est ni sauvegardé ni cherché : les dossiers recréables et le contenu ignoré par .gitignore ; JAMAIS .git (historique), qui est caché mais sauvegardé.
- PROJET SUIVI EN PLACE : option (pas le défaut) : le projet reste à sa place sur le PC, le Coffre l'affiche, le cherche et le sauvegarde sur le disque, sans en être propriétaire.
- ORIGINAL : le fichier ou dossier resté à son ancienne place après un dépôt par copie.

## A — Plus jamais de page figée : tâches de fond et progression (PREMIER commit)

1. Reproduire d'abord les deux problèmes de Thomas et les expliquer dans le rapport : (a) 7 fichiers déposés d'un coup → interface figée ; (b) un projet React réaliste (~30 000 fichiers dont node_modules) → figé puis échec, fichiers non créés. Trouver la vraie cause (requête HTTP trop longue, travail synchrone, mémoire, délai d'attente…).
2. Règle générale (à écrire dans MODULES.md) : toute opération qui peut durer plus d'une seconde (dépôt, analyse d'un dossier, copie, import, déplacement de dossier, mise à jour du disque, archivage, extraction, libération des originaux) est une TÂCHE DE FOND : la requête rend la main tout de suite (identifiant de tâche), l'interface suit l'avancement (flux d'événements ou interrogation), jamais une requête qui attend la fin.
3. Panneau des tâches (visible depuis tout le Coffre, et témoin dans la barre latérale) : pour chaque tâche, ce qu'elle fait, « 1 234 / 5 000 fichiers », le fichier en cours, le temps restant estimé, Annuler ; plusieurs tâches listées ; à la fin un compte rendu (« 4 998 rangés, 2 erreurs ») avec la raison de CHAQUE erreur et « Réessayer ceux-là ». Jamais d'échec silencieux, jamais de fichier perdu : un fichier qui échoue reste à sa place d'origine et est listé.
4. Analyse d'un dossier déposé : les dossiers cachés/exclus sont écartés AVANT de compter, d'empreinter et de copier (un projet React redevient petit). Au-delà d'un seuil (ex. 20 000 fichiers après exclusions ou 20 Go), avertir avec les chiffres avant de commencer (« Continuer » / « Choisir ce qu'on garde »).
5. Débit : empreintes et copies en flux, en parallèle mesuré (pas de saturation du disque), interface fluide pendant le travail (mesure : temps de réponse de l'API pendant le dépôt du projet React).

## C — Le badge Projet (fin de route)

1. Proposé automatiquement (règle projectMarker de la v0.48 : marqueurs .git, package.json, pyproject.toml, requirements.txt, Cargo.toml, platformio.ini, *.sln, CMakeLists.txt… ou fichiers de code), avec sa raison visible (« contient du code : main.py, .git ») ; Thomas peut l'activer ou l'enlever sur n'importe quel dossier, à tout moment, d'un clic (menu, en-tête du dossier) ; aucun fichier déplacé ; Annuler.

## D — Carte, arbre et vue d'un dossier

1. Carte et arbre (v0.48) : uniquement les dossiers de rangement ; un projet = UN nœud feuille avec son badge ; jamais ses sous-dossiers ; jamais de dossier caché. Les nombres d'éléments comptent les fichiers (hors exclus) du dossier et de ses descendants.
2. Ouvrir n'importe quel dossier = l'EXPLORATEUR (même composant pour tous) :
   - dossier normal : en-tête (nom, route, nombre de fichiers, état disque), sous-dossiers et fichiers en cartes ou en liste (choix retenu), pastilles de filtres, déposer ici ;
   - projet : façon dépôt GitHub : arborescence intérieure à gauche (sans dossiers cachés sauf case cochée), fichier sélectionné à droite affiché par son LECTEUR, README par défaut (sinon la liste des fichiers en cartes) ; en-tête avec branche et dernier commit si .git (lecture seule) ; recherche dans le projet, Ctrl+P ; clavier (↑ ↓ → ← Entrée) ; lecture seule (on modifie dans VS Code ou l'application du fichier).
3. Sur chaque fichier : Ouvrir (règles v0.47.1 : code → VS Code sur le projet, positionné sur le fichier ; jamais l'application associée pour un fichier qui exécute du code sans confirmation), Lire en plein écran, Afficher dans l'explorateur Windows, Copier le chemin, Versions.

## E — Projet = unité indivisible

1. Déplacer, archiver, réactiver, supprimer, changer de route : toujours le projet ENTIER. Les fichiers d'un projet ne peuvent pas être déplacés, archivés ou supprimés un par un depuis le Coffre (actions absentes, avec la raison) ; ouvrir, lire, voir les versions, ajouter des fichiers DANS le projet (jamais écraser : « garder les deux / annuler ») restent possibles.
2. Sur le disque externe : un projet est toujours complet et cohérent. La mise à jour ne recopie que les fichiers ajoutés ou modifiés (manifeste par fichier), retire vers l'historique ce qui a été supprimé ou renommé ; le projet n'est marqué « actif » (à jour) que lorsque TOUS ses fichiers correspondent ; une mise à jour interrompue le laisse « pas encore sur le disque » et se termine à la suivante.
3. Historique par fichier dans un projet ; « Versions » par fichier ; restaurer la version d'un fichier (confirmation + Annuler) ; quota FIFO inchangé.
4. Git : ne jamais copier un projet pendant que Git écrit (.git/index.lock ou autre .lock) → reporté à la fin de la mise à jour puis réessayé ; aucune commande git lancée par ToolBox.
5. Projets copiés en bloc sur le disque avant cette version : passage au manifeste sans recopie (empreintes comparées), sans perte.

## F — Fichiers de projet trouvables un par un

1. Recherche (Coffre et Ctrl+K) : chaque fichier d'un projet est un résultat à part entière, par NOM et par CONTENU : « main.py — Cours/GPU/Labos (projet) », extrait, ligne ou page ; ouvrir → CE fichier.
2. Vues par tag / attribut (« Python », PDF…) : incluent les fichiers des projets, marqués de leur projet.
3. Exclus jamais cherchés.

## G — Déposer un dossier : il arrive tel quel

1. Déposer un dossier (glisser, clic droit Windows, Gestion › Importer) = il arrive TEL QUEL à la route choisie (sélecteur v0.48), avec toute son arborescence ; JAMAIS éclaté. Ses sous-dossiers deviennent des dossiers du Coffre ; ceux qui ressemblent à des projets reçoivent le badge proposé (fin de route), visible et modifiable dans l'aperçu.
2. L'aperçu de la v0.48 (arbre, nombres, tailles, doublons, exclus, fusion avec un dossier de même route) reste pour les gros dossiers ; il montre les badges Projet proposés.
3. Défaut : COPIE dans le Coffre (choix de Thomas). Option « Laisser en place et le suivre » toujours disponible au dépôt, et conversion copie ↔ suivi plus tard (jamais deux versions vivantes sans le dire ; l'ancienne copie en corbeille seulement après succès ; Annuler).
4. La copie ne vieillit pas en silence : pour un dossier ou projet copié, ToolBox retient le chemin de l'original. Après la copie, un message dit où l'original se trouve encore et propose : « Travailler dans la copie (Ouvrir dans VS Code) » / « Le suivre en place à la place ». Ensuite, au regard périodique, si l'original existe encore et a changé depuis la copie (dates/tailles puis empreintes) : signal « L'original de Projet_Robot a changé depuis la copie » → « Mettre la copie à jour depuis l'original » (un clic : seuls les fichiers changés, anciennes versions gardées dans l'historique) / « Le suivre en place » / « Ne plus surveiller cet original ». Rien n'est jamais fait sans clic. Si la copie ET l'original ont changé : montrer les fichiers en conflit, ne rien écraser, laisser choisir fichier par fichier.
5. Adoption d'un dossier copié à la main dans le coffre (v0.48) : mêmes règles.

## H — Deux risques du rapport v0.48.0

1. Mise à jour du disque PENDANT un dépôt/import : bloquée avec un message clair ; proposée dès la fin.
2. Reprise d'un dossier ou projet après un arrêt entre la mise en place et l'écriture de la fiche : jamais de « nom (2) » ; reconnaître ce qui est déjà en place (empreintes) et terminer. Test qui simule l'arrêt.

## I — Libérer les originaux (supprimer les doublons restés à leur ancienne place)

1. ToolBox retient, pour chaque fichier et chaque dossier déposé (dépôt, clic droit Windows, Téléchargements, import), le chemin de l'ORIGINAL et son empreinte au moment du dépôt (pour un dossier : manifeste de ses fichiers, hors exclus). Éléments déposés avant cette version : chemin d'origine retenu si connu, sinon rien (jamais deviné).
2. Gestion › « Libérer de la place sur le PC » : liste des originaux encore présents, regroupés par dossier d'origine (Téléchargements, Documents…), avec la place totale récupérable. Un original n'est SUPPRIMABLE que si, vérifié AU MOMENT de la suppression (relecture, pas seulement la base) :
   a. la copie du Coffre a la même empreinte que l'original ;
   b. une copie vérifiée existe sur le disque externe (état « actif » ou « archivé », empreinte relue sur le disque branché) — toujours deux copies quand l'original disparaît ;
   c. l'original n'a pas changé depuis le dépôt.
   Sinon il est listé « non supprimable » avec sa raison (« pas encore sur le disque », « modifié depuis le dépôt », « disque absent », « copie du Coffre différente »). Disque non branché : rien n'est supprimable (le dire).
3. Pour un dossier ou un projet : supprimable seulement si TOUS ses fichiers (hors exclus) remplissent a, b et c ; les fichiers exclus de l'original (node_modules…) partent avec lui (le dire et donner la place).
4. Suppression : dans la CORBEILLE DE WINDOWS (jamais définitive), après sélection et confirmation qui dit combien de fichiers et de Go ; tâche de fond avec progression ; compte rendu ; un original qui échoue reste en place et est listé. Rien n'est jamais supprimé sans ce clic.
5. Après suppression, le Coffre arrête de surveiller cet original (G.4) et la fiche garde « original libéré le … depuis <chemin> ».
