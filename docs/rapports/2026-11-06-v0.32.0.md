# Rapport de session — v0.32.0 (06/11/2026)

Session « Version téléphone, étape 5a : moteur de synchro PC ↔ téléphone (appairage + synchro déclenchée à la main) ».

## Guide pour Thomas (à faire en premier)

### 1. Mettre à jour le PC et le téléphone (même version : 0.32.0)

1. **PC** : installe la 0.32.0 (le `.exe` de la CI Windows : [run 128](https://github.com/Near1807/ToolBox/actions/runs/42211413175), ou la Release GitHub 0.32.0 publiée par ce run), comme d'habitude. Attendu : ToolBox s'ouvre normalement ; rien ne change tant que tu n'actives pas la synchro.
2. **Téléphone** : télécharge l'APK 0.32.0 sur le S21 :
   https://github.com/Near1807/ToolBox/actions/runs/42209377834/artifacts/13498213199
   Extrais le `.zip`, touche `ToolBox-0.32.0.apk` › **Mettre à jour** (ne désinstalle pas).
   - Empreinte à vérifier dans le journal du run (https://github.com/Near1807/ToolBox/actions/runs/42209377834 › build › « Check the APK… ») : `60:CA:57:71:C8:2B:E1:75:11:26:C2:2E:54:9E:98:AC:5C:8A:5F:72:AC:0E:5D:83:BB:E8:36:69:7D:DC:48:5F` (la même que la 0.31.0 et que `LISEZ-MOI.txt`).
   - Attendu à l'ouverture : tes données sont là. Dans **Plus › Réglages › Copies de sauvegarde › Restaurer une copie**, une copie « avant une mise à jour des données » vient d'être prise (n'en restaure pas : **Annuler**).

### 2. Activer la synchro sur le PC (pare-feu)

1. PC : **Réglages › Synchro avec le téléphone** › **Activer la synchro**.
2. Une confirmation explique ce qui va se passer : le PC écoute sur ton réseau local (port 47400), en HTTPS, seulement pour les téléphones appairés › **OK**.
3. **Windows affiche « Pare-feu Windows Defender a bloqué certaines fonctionnalités… »** pour ToolBox : coche **Réseaux privés** (ton Wi-Fi du kot), **décoche Réseaux publics**, puis **Autoriser l'accès**.
   - Attendu : « Activée : écoute sur le réseau local, port 47400. Adresse du PC : 192.168.… ».
   - Si la fenêtre du pare-feu n'apparaît pas et que le téléphone ne joint pas le PC : Paramètres Windows › Confidentialité et sécurité › Sécurité Windows › Pare-feu › « Autoriser une application » › ToolBox › Privé coché.

### 3. Appairer par le QR code

1. PC : **Appairer un téléphone**. Attendu : un QR code et, à côté, le même code en texte (`TBX1-…`), valable 10 minutes et une seule fois.
2. Téléphone : **Plus › Réglages › Synchro avec le PC › Ouvrir la synchro** › **Photographier le QR code** › prends l'écran du PC en photo (bien net, tout le QR dans l'image).
   - Si la photo ne marche pas : tape le code dans le champ, puis **Appairer avec ce code** (les tirets et les espaces ne comptent pas ; une faute de frappe est détectée).
   - Attendu : « PC appairé » et, juste en dessous, la carte **Première synchro**. Sur le PC, sous « Appareils appairés » : « Téléphone ».

### 4. Première synchro : « Partir des données du PC »

1. Téléphone : **Voir l'aperçu**. Attendu : une ligne par module (« PC → téléphone : … · téléphone → PC : … ») et, s'il y en a, les noms présents des deux côtés (Riz, Œuf… et les 4 moments par défaut). Rien n'est écrit pendant l'aperçu.
2. **Partir des données du PC** › lis la confirmation › **OK**.
   - Attendu : « Première synchro faite ».
   - Le téléphone a pris une copie « avant-synchro » (Réglages › Restaurer une copie), et le PC une sauvegarde `hub-…-avant-synchro.db` (Réglages › Sauvegardes).
3. Vérifie des deux côtés quelques éléments : tes tâches, tes recettes et ingrédients (tes essais Riz, Œuf, Oignon, « Riz sauté » ont disparu du téléphone : ils sont dans la copie), ta semaine type du Sport, tes idées, tes préréglages du Timer, tes objectifs des Courses.
   - Les photos des recettes du PC n'arrivent pas encore sur le téléphone (étape 5b) : la recette s'affiche sans image.

### 5. Synchroniser à la main, dans les deux sens

1. Téléphone : coche une tâche (ou change un titre). Puis **Accueil › Synchro avec le PC › Synchroniser** (aussi dans Réglages › Synchro avec le PC).
   - Attendu : « Synchronisé : 0 reçu, 1 envoyé, 0 conflit ». Sur le PC, la tâche est cochée (rouvre la page To-do).
2. PC : ajoute une tâche. Téléphone : **Synchroniser**. Attendu : « 1 reçu, 0 envoyé, 0 conflit », la tâche est sur le téléphone.
3. Essaie un conflit : sans synchroniser, change le même titre sur les deux, puis **Synchroniser**. Attendu : « … 1 conflit » ; le titre modifié en dernier gagne sur les deux.
4. Hors réseau (Wi-Fi coupé, ou ToolBox fermé sur le PC) : **Synchroniser** affiche « Le PC ne répond pas… Rien n'est perdu ». Reconnecte-toi et resynchronise : les changements partent.

### 6. Où voir les conflits

- Téléphone : **Synchro avec le PC › Voir les conflits**.
- PC : **Réglages › Synchro avec le téléphone**, carte « Conflits ».

Chaque conflit montre la valeur gardée, la valeur écartée, l'appareil de chacune et la date. **Vu** le retire de la liste (rien ne change dans les données). Pour deux ingrédients ou deux exercices du même nom, **Fusionner** utilise la fusion existante du module.

### 7. Oublier un appareil

- PC : **Réglages › Synchro avec le téléphone › Appareils appairés › Oublier cet appareil** (confirmation). Son accès est révoqué tout de suite : la synchro suivante du téléphone dit « n'est plus reconnu par le PC ». Ses données restent sur lui.
- Téléphone : **Synchro avec le PC › Oublier ce PC** (le téléphone arrête seulement de se synchroniser).
- Pour couper l'écoute réseau du PC : **Désactiver**.

## 1. Résumé

- Le **moteur de synchro** est fait et partagé par le PC et le téléphone : horloge hybride, champ par champ, conflits gardés, tout ou rien, idempotent. Il est testé sur deux vraies bases (better-sqlite3 et sqlite-wasm) pour les 5 modules.
- **Appairage** par QR code ou code tapé : écouteur HTTPS du PC désactivé par défaut, certificat épinglé, jeton par appareil révocable.
- **Première synchro** avec aperçu et deux choix ; **synchro à la main** avec résumé ; écrans **Conflits** sur les deux appareils.
- PC sans appairage : comportement identique, aucun port ouvert ; références des 5 modules vertes (colonnes de suivi exclues). 950 tests verts.
- **Le réseau Android (greffon épinglé, QR par photo, pare-feu Windows) est non testé en réel** : vérifié par les tests Node et dans Chromium.

## 2. Ce qui a été fait

### Partie 1 : socle et moteur (`30f5509`)

- **Migrations (ajouts seulement)** :
  - socle v6 : `core__sync_peers`, `core__sync_cursors`, `core__sync_conflicts`, `core__changes` (journal des réglages synchronisés), `core__field_clock` ;
  - une migration par module synchronisé (todo 3, ideas 3, timer 3, sport 4, courses 7) : `hlc`, `origin`, `seq` dans le journal (`seq` rempli dans l'ordre existant), `<module>__field_clock` ;
  - sauvegarde avant migration sur le PC (existante), copie « avant-migration » sur le téléphone (vérifiée, §7).
- **Horloge hybride** (`backend/core/sync/hlc.ts`) : heure, compteur, appareil ; jamais en arrière, même après un redémarrage ou une horloge reculée ; elle avance au-delà de ce qui est reçu.
- **SyncStore** écrit l'HLC, l'ordre et l'horloge de chaque champ ; `syncStamp` reste pour `at` / `updated_at` mais ne décide plus du « plus récent ».
- **Moteur** (`backend/core/sync/engine.ts`, portable) :
  - lot depuis un curseur, sans renvoyer à un appareil ses propres changements ;
  - application champ par champ, une transaction, idempotente (un changement déjà connu est sauté) ;
  - noms et colonnes vérifiés : seules les tables des modules qui déclarent `sync`, jamais le journal, `*_v1`, `legacy_ids`, ni la musique.
- **Conflits** : même champ modifié des deux côtés entre deux échanges → la HLC la plus récente gagne, l'autre valeur est gardée (`core__sync_conflicts`), sur le PC et recopiée sur le téléphone.
- **Supprimé d'un côté, modifié de l'autre** : la ligne reste supprimée (restaurable) avec les modifications, et c'est listé (« supprimé ici, modifié sur l'autre appareil »).
- **Noms en double** (ingrédients, préparations, repas, moments, exercices, préréglages du Timer) : jamais fusionnés seuls, listés. **Fusionner** existe pour les ingrédients et les exercices ; signalés seulement pour les autres (pas de fusion dans le module).
- **Clé unique en double**, que la base ne peut pas garder deux fois : tag de la Boîte à idées (même nom), semaine du Sport. La ligne du PC reste ; l'autre prend son identifiant et ses valeurs, et ses anciennes valeurs vont dans « Conflits ».
- **Sport, ta règle** : semaine remplie sur les deux appareils → celle du PC gardée ; les séances générées par le téléphone et jamais touchées passent en suppression logique ; une séance modifiée reste et est listée. Décidé sur le PC en fin de lot et renvoyé dans le même échange.
- **Réglages** : `sync: true` dans le manifest pour un réglage de données.
- **Protocole** (`protocol.ts`) : versions comparées à chaque échange, échange à la main en trois temps, première synchro.

## 4. Décisions prises sans Thomas

- **Colonnes de synchro ajoutées par une migration de chaque module**, pas par le socle. Raison : la règle d'or interdit au socle de toucher les tables d'un module ; le SDK fournit `syncJournalSql`. Pour changer : rien à faire, c'est transparent.
- **Clé unique en double** (tag de même nom, semaine) : la ligne du PC gardée, l'autre adopte son id et ses valeurs, et ses valeurs vont dans « Conflits ». Raison : la base ne peut pas en garder deux. Pour les tags, c'est donc une fusion forcée par la base (seule la couleur peut différer), listée.
- **Règle des doublons appliquée par le PC seul**, en fin de lot. Raison : le PC reçoit toujours les changements du téléphone en premier, et sa décision repart dans la même réponse (une seule vérité, pas de deuxième tour).
- **Pas d'auto-fusion des 4 moments par défaut** (Matin, Midi, Collation, Soir), créés par chaque appareil à son premier lancement : avec « Fusionner », ils apparaissent comme 4 noms en double, sans fusion possible. Avec « Partir des données du PC », la question ne se pose pas.
- **QR lu sur une photo** (pas de caméra en direct). Raison : aucun greffon ni permission en plus ; marche avec le sélecteur photo déjà utilisé pour les recettes.
- **Jeton d'appareil gardé en clair dans la base du téléphone** (stockage privé de l'appli, OPFS). Le PC n'en garde que l'empreinte.
- **Port fixe 47400**, pour que le pare-feu et le QR restent valables d'un lancement à l'autre.
- **Changement d'un champ de clé unique qui créerait un doublon** (renommer un tag vers un nom déjà pris, de l'autre côté) : ce changement n'est pas appliqué, il est listé.
- **Option `backupDb` des tests** et assistant toujours sans effet sur le téléphone : inchangé.

## 5. Écarts par rapport à la demande

- « Même nom … jamais de fusion automatique » : respecté partout **sauf les tags de la Boîte à idées et les semaines du Sport**, que la base ne peut pas contenir deux fois (contrainte d'unicité existante). Ces cas sont réglés comme ci-dessus et toujours listés dans « Conflits ».
- « Seq » et « HLC dans les journaux » : ajoutés par des migrations de **module**, pas du socle (voir §4).
- Les conflits trouvés par le PC pendant un échange sont **recopiés** sur le téléphone (même liste des deux côtés) ; un conflit vu sur le téléphone n'est « Vu » que sur lui.

## 9. Risques et points à surveiller

- **Réseau du kot** : si le Wi-Fi isole les appareils (« isolation des clients »), le téléphone ne joint pas le PC. Ton test du 05/11 dit que non.
- **Adresse du PC qui change** (DHCP) : le téléphone garde l'adresse du QR. Si elle change, il faut appairer de nouveau (le repérage automatique viendra en 5b).
- **Taille des échanges** : une première synchro envoie toutes les données en une fois (limite 64 Mo). C'est sans souci pour du texte, et les photos ne voyagent pas encore.
- **Écrans ouverts pendant une synchro** : ils ne se rafraîchissent pas tout seuls ; ils reprennent les nouvelles données en changeant de page.
- **Timer pendant une synchro** : une session lancée sur un appareil reste à lui ; la règle « deux appareils » viendra en 5b.
- **Historique d'avant la synchro** : les changements faits avant la 0.32.0 ne voyagent pas un par un ; la première synchro les couvre par l'instantané complet.
