# Rapport de session — v0.16.0 (To-do et Assistant vocal V1) — 2026-10-23

## 1. Résumé

Deux nouveaux modules dans la section **Outils**, poussés ensemble sur `hub-v1`, 100 % gratuits et locaux :

- **To-do** : terminée et vérifiée en interface.
- **Assistant vocal** : une chaîne locale complète (whisper.cpp → Ollama → Piper) et un talkie-walkie. Il agit sur la To-do et lit les autres outils grâce à une nouvelle règle du contrat : chaque module expose ses actions, avec un niveau de risque appliqué par le socle.

Testé avec de faux moteurs, puis en partie avec les **vrais** binaires `whisper-server` 1.9.2 et Ollama 0.32.15 et un petit modèle de test. Ce test réel a trouvé et fait corriger quatre défauts. Les modèles recommandés (Ministral 3, Whisper Small, voix Piper) et la touche Copilot n'ont pas pu être essayés ici : **non testés en réel**, à faire sur le PC de Thomas (§8).

## 2. Ce qui a été fait

- **Socle (`92a6479`)** :
  - **Registre d'actions `ctx.assistant`** (`backend/core/assistant.ts`) :
    - un module déclare des actions (nom, description française, paramètres typés, risque `read` / `change` / `destructive` / `sensitive`) ;
    - le socle vérifie les paramètres (et corrige ce que les modèles envoient souvent : `"3"`, `"a, b"`) ;
    - il exécute directement lectures et modifications et garde les « Annuler » en mémoire ;
    - il refuse une action destructrice sans `confirmed` et n'exécute jamais une action sensible ;
    - actions du socle : tâches en cours, liste des outils, ouvrir un outil ou une page (`assistant-core.ts`).
  - **Touche globale `ctx.hotkeys`** (`hotkeys.ts`, `electron/global-keys.ts`) avec `uiohook-napi` (N-API précompilé, comme better-sqlite3) : appui **et** relâchement même sans le focus, capture « appuie sur la touche voulue ».
  - **`ctx.ui`** : ouvrir une page (fenêtre montrée) ; **indicateur flottant** (`electron/overlay.ts`, route `#/overlay`) ; composants `Background` et `Overlay` des modules (`frontend/src/modules/ModuleExtras.tsx`).
  - **Permissions** de l'interface limitées aux pages de l'app, et au micro seul parmi les périphériques.
  - Réglages `hidden`.
  - Documentation : MODULES.md §5.15–5.16 et §7, AJOUTER-UN-MODULE (étape 6), ARCHITECTURE, ADR 0028. Le module modèle `_template` déclare deux actions.
- **To-do (`fcf3267`)**, `modules/todo/` :
  - tâches (titre, tags, échéance, « Fait », date de création), migration 1 ;
  - **échéances en français** (`dates.ts`, 55 cas testés) : « demain », « vendredi prochain », « lundi en huit », « dans quinze jours », « le premier décembre », « 12/11 »… ; rien n'est deviné ;
  - ajout rapide au clavier avec aperçu (« finir le mix #mix vendredi » + Entrée) ;
  - modification sur place, suppression confirmée, « Annuler » (composant partagé `UndoToast`) ;

  - Bibliothèque : morceaux, état d'un projet, ouvrir une fiche ;

  - Pack Insta, Reels perso : état ;
  - tests dans chaque module.
- **Assistant vocal (`61ca97d`, `635423d`, `ebfa281`)**, `modules/assistant/` :
  - **Moteurs** (`engines.ts`) : `whisper-server` gardé lancé (requête HTTP locale) ; Piper gardé lancé (une phrase par ligne → un WAV) ; lecture dès la première phrase.
  - **Ollama** (`ollama.ts`) : version, modèles, capacités, téléchargement avec progression, chat avec outils en flux, erreurs traduites.
  - **Cerveau** (`brain.ts`) :
    - les outils sont les actions de tous les modules ;
    - après une modification, la phrase dite est le message de l'action ;
    - une suppression attend un « oui » reconnu par le code ;
    - une action sensible est refusée, puis « Je l'ouvre ? » ;
    - garde d'honnêteté : une phrase « J'ai ajouté… » sans résultat d'outil n'est jamais dite ;
    - contexte de session ;
    - limites : 400 jetons par réponse, 2 minutes par échange.
  - **Talkie-walkie** : maintenir pour parler, ou appuyer / appuyer (automatique si relâché en moins de 0,35 s) ; 30 s au plus ; reparler coupe la réponse.
  - **Installation guidée** (`catalog.ts`, `hardware.ts`, `download.ts`) :

    - étapes pas à pas pour Ollama.
  - **Page** : conversation (entendu, réponse, actions avec « Annuler », Oui / Non, « Ouvrir la page »), saisie au clavier, micro, latence de chaque maillon, modèles et réglages.
  - **Background** : micro en WAV 16 kHz, lecture.
  - **Indicateur flottant** : écoute / réflexion / réponse.

## 4. Décisions prises sans Thomas

- **Ollama installé à part**, pas embarqué : installateur officiel, mises à jour faites par Ollama ; l'app guide (télécharger, installer, « Démarrer Ollama », « Vérifier »).
- **Modèle recommandé : Ministral 3** (Mistral AI : outils natifs, très bon en français) : 3B sans carte graphique NVIDIA, 8B dès 8 Go de VRAM, 14B dès 12 Go. Alternatives : Qwen 3.5, Mistral Small 3.2, ou n'importe quelle étiquette. _Pour changer_ : `MODEL_CHOICES` et `recommend()` (`catalog.ts`, `hardware.ts`).

- **Noms des niveaux de risque dans le code** : `read` (lecture), `change` (modification sans conséquence), `destructive` (modification destructrice), `sensitive` (sensible).
- **Sensibles déclarées** : envoyer sur YouTube, publier, déplacer une date (Planning). Elles sont connues de l'assistant, qui les refuse et propose la page.
- **Réponse après une lecture** : reformulée par le modèle (plus naturelle), option « Réponses directes » pour lire le résultat tel quel (plus rapide). Après une modification : toujours le message exact de l'action.
- **« vendredi » dit un vendredi** = le vendredi suivant (« aujourd'hui » se dit autrement) ; « dans quinze jours » = 14 jours, « dans huit jours » = 7.

- **Micro ouvert seulement pendant l'écoute** (pas de micro permanent). Le tout début d'une phrase prononcée trop vite peut être coupé (~0,2 s).
- **Crochet clavier actif tant que l'assistant est chargé**, pour la touche par défaut. Seul le code de cette touche est regardé.
- **Historique et contexte en mémoire** seulement, oubliés à la fermeture. Une tâche supprimée est gardée une heure en mémoire pour « Annuler ».
- **Performances** :
  - heure arrondie dans les instructions (cache d'Ollama valable une heure) ;
  - instructions et outils lus au démarrage ;
  - 400 jetons au plus par réponse, 2 minutes par échange.
- **Indicateur** : centré en bas de l'écran principal, caché 2,5 s après la fin.

## 5. Écarts par rapport à la demande

- **Touche Copilot** : elle marche comme touche « parler », mais avec deux limites qu'une app hors Microsoft Store ne peut pas supprimer proprement :
  - Windows ouvre aussi Copilot (ou la Recherche) ;
  - sur certains PC, la touche envoie son relâchement tout de suite.
    Ce qui est fait :
  - mode appui / appui automatique ;
  - explication dans la page, avec l'alternative propre : PowerToys « Remapper un raccourci » Win+Maj+F23 → F24, ou une autre touche.
- **Rattachement To-do ↔ morceau sur la fiche** : une ligne d'information (« To-do : 2 à faire : … »), pas une liste interactive. C'est ce que la Bibliothèque permet sans modification.
- **Recommandation de modèle** : étiquettes non vérifiables sur ollama.com depuis ici. L'app contrôle la capacité « tools » après le téléchargement et le dit si elle manque.
- **Test réel** : partiel (§3, §7).

## 6. Bugs trouvés

Corrigés pendant la session :

- **Ollama sans limite de longueur** (trouvé en réel) : le modèle de test a généré plus de 6 800 jetons sans s'arrêter. Corrigé : 400 jetons par réponse, 2 minutes par échange.
- **Cache d'Ollama cassé à chaque minute** (trouvé en réel) : l'heure exacte dans les instructions forçait à tout relire (un échange passait de 2 s à 14 s). Corrigé : heure arrondie, et lecture des outils au démarrage.
- **Modèle sans appel d'outils** (trouvé en réel) : l'échange échouait. Il répond maintenant aux questions et dit qu'il ne peut pas agir.
- **Erreurs d'Ollama en anglais brut** (« Forbidden », « does not support tools ») : traduites.
- **To-do** : la date proposée en modification (« mer. 21 oct. ») n'était pas relue. Elle est maintenant au format 21/10/2026.
- **Mise en page** : le panneau « Modèles et réglages » débordait (longues options) ; corrigé.
- **Fiche du morceau** : le texte « les statistiques arriveront avec l'outil Statistiques YouTube » datait d'avant la v0.15.0. Il renvoie maintenant vers Stats YouTube.

Aucun bug trouvé dans les modules existants hors ce texte.

## 9. Risques et points à surveiller

- **Latence sans carte graphique** : la liste des outils (~2 400 jetons) est relue à chaque échange si le modèle de prompt du modèle la place près de la question (c'est le cas de certains modèles Mistral). Sur un processeur, cela peut coûter des dizaines de secondes. À mesurer (§8.6) ; pistes si trop lent :
  - un modèle dont le prompt place les outils au début (Qwen) ;
  - moins d'outils par demande ;
  - une carte graphique.
- **Étiquettes Ollama non vérifiées** (`ministral-3:3b`…) : si le téléchargement dit « modèle inconnu », saisir l'étiquette exacte d'ollama.com/library.
- **Piper archivé** : le binaire de 2023 n'évoluera plus ; il fonctionne avec les voix actuelles (même format).
- **Crochet clavier** : un antivirus peut s'en méfier (c'est la technique des logiciels de touche globale) ; ToolBox ne regarde que la touche choisie.
- **Micro Windows** : les apps de bureau doivent être autorisées (Paramètres › Confidentialité › Microphone).
- **Indicateur flottant** : seulement sur l'écran principal ; non vérifié avec plusieurs écrans ni en plein écran d'un jeu.
- **Espace disque** : 4 à 12 Go selon le modèle (vérifié avant chaque téléchargement).
- **Port de whisper-server** choisi au hasard sur 127.0.0.1 à chaque lancement : non accessible depuis le réseau.
