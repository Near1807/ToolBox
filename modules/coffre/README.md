# Coffre (`coffre`, Expérimental)

Un seul endroit pour **garder, ranger, retrouver et ouvrir** les fichiers qui comptent. Cahier des charges complet : [`docs/coffre/CAHIER-DES-CHARGES.md`](../../docs/coffre/CAHIER-DES-CHARGES.md). ADR 0051 (socle), 0053 (pages et lecteurs), 0054 (socle : dossier externe, copie de la base, indicateur), 0055 (le disque externe), **0067 (v0.50.0 : le modèle « tout est dossier », qui remplace celui des v0.45–v0.49)**, **0068 (v0.51.0 : projets avancés)**.

PC seulement (`PC_ONLY_MODULES`) ; dépendance facultative : le service `agenda` (cours importés).

## Le modèle (v0.50.0, Expérimental)

- **Dossier** : la seule façon de ranger ; une **route** = son chemin (« Cours › Réseaux › Slides »). Un **fichier** est à un seul endroit.
- **Étiquettes** par famille (Nature, Langage, Année, Origine + site, Cours, Prof, libres) : déduites (« deviné » + raison) ou choisies ; une étiquette choisie n'est jamais remplacée par une déduction. **Étiquettes par défaut** d'un dossier : proposées aux fichiers qui y arrivent (le dossier le plus proche l'emporte), jamais ajoutées aux fichiers déjà là sans « Appliquer aux fichiers déjà présents » (aperçu, Annuler). **Ensembles** nommés (« Slides de cours ») ; copier (Ctrl+Maj+C) / coller (Ctrl+Maj+V, Ajouter ou Remplacer, Annuler).
- **Fin de route** : un dossier dont l'intérieur se lit dans ToolBox (arbre à gauche, lecteur à droite, README par défaut, ↑ ↓ → ← Entrée, Ctrl+P) ; la carte s'arrête là.
- **Projet** : une Fin de route **indivisible** (une seule entrée `kind = 'project'` ; le disque le copie, l'archive et le vérifie entier ; VS Code ; branche et dernier commit lus dans `.git`, sans commande git). Proposé à l'arrivée d'un dossier (`.git`, `package.json`, code… avec la raison), jamais posé seul ; un projet dans un projet : seul le plus haut compte. Les dépendances (`node_modules`…) restent de côté ; `.git` est toujours gardé.
- **Dossier caché** (nom en point, dépendances) : pas sur la carte, montré à l'intérieur d'une Fin de route avec la case « Afficher les dossiers cachés ».
- **À ranger** : un fichier sans dossier (`folder_id` nul), en haut de la carte avec son compteur.
- **Original** : son chemin et son empreinte sont retenus ; il n'est jamais modifié ni déplacé.

## Projets avancés (v0.51.0, Expérimental, ADR 0068)

- **Fichiers intérieurs** : `backend/inner.ts` (`ProjectIndex` : index par projet, relu seulement pour ce qui a changé ; manifeste du disque) ; chaque fichier intérieur est un résultat de recherche (nom, contenu, ligne ou page : `backend/search.ts`, texte lu fichier par fichier dans `backend/text-index.ts`) ; ouvert seul (`c/<dossier>?f=…&line=…`, `lire/<projet>?f=…`, VS Code `-g fichier:ligne`) ; vues par étiquette groupées par projet (`GET /inner-files`). Pas de fiche par fichier intérieur.
- **Exclusions** : `backend/exclusions.ts` (liste par défaut + `.gitignore` par la bibliothèque `ignore` + choix par projet ; `.git` jamais exclu).
- **Disque fichier par fichier** : `backend/project-update.ts` (copie des seuls fichiers ajoutés ou modifiés, anciennes versions dans l'historique, adoption des copies v0.50 sans recopie, report si Git écrit, proposition de retirer ce qui n'est plus sauvegardé).
- **Git** : `backend/git.ts` (lecture seule : branche, dernier commit, verrou, modifications non commitées par l'index de git ; aucune commande).
- **Suivi en place** : `backend/tracked.ts` (`tracked_path` : jamais déplacé, archivé ni supprimé par le Coffre ; introuvable / « Le retrouver… » ; conversions) ; interface `frontend/Tracked.tsx`.

## Sur le disque du PC

`userData/coffre/` (`ctx.files.libraryDir`), lisible sans ToolBox :

- `Cours/Réseaux/Slides/cours1.pptx` : un fichier rangé (chemin = route ; les étiquettes ne sont jamais dans le chemin) ;
- `Programmation/auto_mail/…` : un projet, tel qu'il est arrivé ;
- `_À ranger/` : déposé, pas encore rangé ;
- `_Corbeille/<id>/` : supprimé, récupérable.

Le Coffre **copie** ce qu'on y dépose. Noms toujours valides sous Windows ; une collision donne « nom (2) ».

## API (`/api/modules/coffre`)

Les opérations longues sont des **tâches de fond** du socle (la route répond `{ jobId }`, ADR 0066) : `deposit/analyze`, `deposit/apply`, `folders/:id/move|merge|reactivate`, `files/archive`, `files/:id/reactivate`, `disk/update|verify`, `restore/apply`, `reset/*`. `backend/tasks.ts` (`taskRoute`), `backend/walk.ts` (parcours, dépendances écartées avant de compter ; seuil `TOOLBOX_COFFRE_WARN_FILES`, 20 000 par défaut, ou 20 Go).

- `GET /home` · `GET /tools` · `GET /courses` · `GET /now` (« Maintenant », ADR 0062)
- Dossiers : `GET /folders` (avec nombres directs et totaux) · `GET /folders/:id` · `POST /folders { parentId, route }` (une route : les dossiers manquants créés, Annuler) · `PATCH /folders/:id { name?, color?, courseName?, defaults? }` · `POST /folders/:id/end { on }` (Fin de route posée / enlevée) · `POST /folders/:id/project` · `DELETE /folders/:id/project` (badge Projet posé / enlevé, aucun fichier ne bouge) · `GET /folders/:id/hint` (Projet proposé et sa raison) · `GET /folders/:id/inside?hidden=1` (l'intérieur d'une Fin de route : arbre, README, branche et dernier commit) · `POST /folders/:id/open { rel, how }` · `POST /folders/:id/defaults/apply { preview? }` · `POST /folders/:id/move|merge|reorder` · `DELETE /folders/:id` (vide seulement) · `GET /folders/:id/content` — `backend/tree.ts` (journal d'opérations, retour arrière, `undoId`)
- Fichiers : `GET /files?folder=&deep=1&family=&value=&pending=1&trash=1&state=` · `GET /files/:id` · `POST /files/create { folderId, name }` (vide ; ce qu'il faut pour l'ouvrir) · `PATCH /files/:id { name?, folderId?, newFolder?, later?, pinned? }` (refusé dans un projet : indivisible) · `PUT /files/:id/labels { family, values }` (« choisi ») · `POST /files/:id/guess` · `POST /files/batch` (« Modifier la sélection », tout ou rien, un `undoId`) · `POST /files/labels/paste { ids, labels, mode: add | replace }` · `GET /labels/values`
- Ensembles : `GET|POST /label-sets` · `PATCH|DELETE /label-sets/:id`
- Corbeille : `DELETE /files/:id` · `POST /files/:id/restore` · `POST /files/:id/erase { confirm: true }` (depuis la corbeille seulement) · `POST /undo { undoId }`
- Ouvrir : `POST /files/:id/open { how: app | folder | vscode, runnable? }` (un exécutable seulement avec `runnable: true`, confirmation qui le nomme ; un fichier de code : VS Code ou l'aperçu, jamais son application) · `POST /files/:id/read-window` · `POST /files/:id/seen`
- Déposer : `POST /deposit/analyze { paths, folderId?, confirmed? }` (propositions : route, étiquettes, projets proposés, dépendances écartées ; rien n'est écrit) · `POST /deposit/apply { entries }` (un dossier arrive **tel quel** ; `projects` = les dossiers acceptés comme projets)
- v0.51.0, projets : `GET /folders/:id/exclusions` · `POST /folders/:id/exclusions { rel, action: exclude | include | reset }` (tâche) · `GET /files/:id/inner?rel=` (un fichier intérieur : lecteur, étiquettes déduites ou du projet) · `POST /files/:id/inner/read-window { rel }` · `GET /inner-files?family=&value=` · `POST /folders/:id/open { rel, how, line }` (VS Code à la ligne) · `GET /files/:id/versions?rel=` (versions d'un fichier) · `GET /disk/excluded` · `POST /disk/excluded/remove { itemIds }` (tâche, vers l'historique) · suivi en place : `POST /folders/:id/relocate { path, confirm? }`, `POST /folders/:id/track { path, mode: copy | existing, confirm? }`, `POST /folders/:id/untrack` (tâches) ; dépôt : `tracked` dans une entrée
- Recherche : `GET /search?q=` (noms, étiquettes, contenu) · `GET /search/status` · `POST /search/refresh` · `GET /files/:id/matches?q=`
- Apprentissage, Téléchargements, fichiers envoyés par Windows, réinitialisation : `GET|PATCH|DELETE /learned…`, `POST /learned/forget`, `GET /downloads…`, `POST /downloads/check|ignore`, `GET /received/:id`, `POST /reset/preview|export|apply`, `GET /reset/pending`, `POST /reset/disk-rename` (`backend/reset.ts`)

## Pages (`frontend/`)

Toutes dans le même cadre (`frame.tsx`) : **glisser n'importe où** ouvre la fenêtre de rangement (sur un dossier : ce dossier est fixé) ; message avec « Annuler » ; Ctrl+K = la recherche du socle ; Ctrl+Maj+C / Ctrl+Maj+V = copier / coller les étiquettes du fichier sélectionné.

- `''` accueil (`Home.tsx`), deux onglets : « Contenu » (À ranger, disque, « Maintenant », épinglés, récents, `Atlas.tsx` = carte `FolderMap.tsx` (disposition `map-layout.ts`) + arbre `FolderTree.tsx`) et « Gestion » (santé, disque, corbeilles, Téléchargements, apprentissage, zone sensible) ; `carte` ;
- `c/:id` un dossier (`Pages.tsx`) : en-tête (nom, route, nombre, état du disque, badges Fin de route / Projet, Projet proposé, étiquettes par défaut `Labels.tsx`), « Nouveau dossier » / « Nouveau fichier… » (`NewItem.tsx`), sous-dossiers, filtres par étiquette, cartes ou liste ; une Fin de route ou un Projet : son intérieur (`Inside.tsx`) ;
- `v/:famille/:valeur` vue par étiquette ; `a-ranger` ; `corbeille` ; `etat/:state` ; `chercher?q=` ; `voir/:id` ; `ranger/:lot` (`Received.tsx`) ; `lire/:id` (fenêtre de lecture, `ReaderPage.tsx`, ADR 0058).

Fenêtre de rangement (`Deposit.tsx`) : aperçu à gauche, fiche à droite (`Sheet.tsx` : route par `RoutePicker.tsx`, étiquettes par famille « deviné » + raison, `Picker.tsx`), Entrée = Ranger, « Ranger plus tard » (À ranger). Un dossier : résumé (fichiers, sous-dossiers, projets proposés à cocher, dépendances écartées) ; il arrive tel quel. Plusieurs fichiers : « Pour tous » (`BatchBlock.tsx`, ensembles, coller), « Tout valider ». « Modifier la sélection » : `BatchEdit.tsx`. Actions sur l'arbre : `folder-actions.tsx`.

Carte d'un fichier (`Items.tsx`, `ReliefCard` du SDK) : aperçu, nom, nature, dossier, date ; clic droit : menu commun (dont Copier / Coller les étiquettes). Espace : aperçu (`Preview.tsx`). Double-clic : son application ; un programme ou un script : jamais sans la question qui le nomme ; un fichier de code : VS Code s'il est installé, sinon l'aperçu (`openPlan`, `frontend/logic.ts`).

Tâches lancées depuis une fenêtre (mise à jour, vérification, restauration du disque) : `useTaskFollow` du SDK et `disk/TaskGauge.tsx` (« Démarrage… » dès le clic, puis la jauge ; jamais deux lancements ; « introuvable » jamais lu comme « terminée ») ; les autres par `runJob` (liste des tâches prévenue tout de suite).

### Lecteurs (`frontend/readers/`)

Registre générique (`registry.ts`) : un lecteur = un fichier `<nom>.reader.tsx` qui appelle `registerReader({ id, extensions, maxBytes?, thumbMaxBytes?, priority?, component })` ; `readers/index.ts` les trouve tous (aucun autre changement). Fournis : PDF (pdf.js, `pdfjs-dist`, worker servi par l'app), images, texte, code coloré (`highlight.js`, langues choisies), Markdown (`markdown-it`, `html: false`, sans images, liens jamais suivis), vidéo et son (lecteurs du navigateur), HTML **isolé** (cadre `sandbox=""`, politique `default-src 'none'` : aucun script, aucune requête). Sans lecteur : l'icône de sa nature et « Ouvrir dans son application ».

v0.47.0 : un lecteur reçoit `locate` (ouvert depuis une recherche : sa page, ses mots, surlignés par `readers/mark.ts`) et `window` (dans la fenêtre de lecture). PDF : pages dessinées quand elles sont vues, couche de texte (sélectionnable, mots surlignés), zoom, « aller à la page », « Chercher dans le document » (↑ ↓) ; code : numéros de ligne ; Markdown : sommaire dans la fenêtre de lecture ; image : zoom.

## Recherche dans le contenu (v0.47.0, ADR 0056)

v0.47.1 : la lecture se fait **dans un worker** (`backend/extract.worker.ts`, `extract-pool.ts` : `worker_threads`, construit dans `build/main/workers/coffre/`, dépaqueté de l'asar) : le fil du serveur reste libre ; 60 s au plus par fichier (sinon « illisible : trop long », relu au démarrage suivant) ; un worker qui s'arrête est remplacé. Un `.docx`/`.pptx`/`.xlsx` n'est jamais décompressé au-delà de 100 Mo (par partie et en tout) ni au-delà de 10 000 parties (`unzipBounded`) : « illisible : trop gros ».

`backend/extract.ts` lit le texte (PDF par page avec pdf.js pour Node, Markdown, texte, HTML sans script ni style, code, `.docx`, `.pptx` par diapositive, `.xlsx` ; un projet : ses fichiers texte ; PDF scanné : « pas de texte », pas d'OCR) ; `backend/text-index.ts` le garde dans l'index FTS5, en arrière-plan (un fichier à la fois, pause de 30 ms, interrompu à la fermeture, repris au démarrage : ce qui reste = ce dont l'empreinte lue n'est pas l'actuelle). Déclencheurs : dépôt, regard sur les fichiers du PC (démarrage, avant une mise à jour du disque, toutes les 10 min), branchement du disque (archivés pas encore lus). Lit seulement le coffre, n'écrit que l'index. Progression dans la zone Santé.

Limites connues : les PDF à images JPEG 2000 ou à polices non incluses s'affichent sans ces images / avec des polices de remplacement (les fichiers WebAssembly et polices de pdf.js ne sont pas chargés : la politique de l'interface n'autorise pas WebAssembly).

## Le disque du coffre (v0.46, ADR 0055)

Réglages › Coffre › « Disque du coffre » : un dossier choisi sur le disque externe ; ToolBox y crée `ToolBox-Coffre/` et `_identite-toolbox-coffre.json`. Le disque est retrouvé par cette identité, jamais par sa lettre (sa dernière place, puis le même chemin sur chaque volume), toutes les 4 s, **en lecture seule** (`backend/volumes.ts`, `disk.ts`). Un seul disque pour l'instant (`coffre__disks` ; une copie par fichier (ou projet) et par disque dans `coffre__copies`).

Sur le disque : le même arbre que sur le PC, et `_ToolBox/` :

- `Historique/<fichier>/<date> nom` ;
- `Corbeille/<fichier>/nom` ;
- `Base/hub.db`, `Base/fiches.json`, `Base/manifeste.json` ;
- `tmp/` (vidé au début de chaque mise à jour), `Deplacement/` et `Abimes/` ;
- `LISEZ-MOI.txt`.

| Partie                                                                                                                                               | Où                                                                        | Ce qui écrit (toujours un clic) |
| ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------- |
| États (« pas encore sur le disque », actif, archivé), fichiers du PC modifiés (taille + date, puis empreinte ; un projet : son empreinte d'ensemble) | `plan.ts`, `disk.ts` (`scanPc`, au démarrage et avant chaque mise à jour) | la base du PC seulement         |

| Archiver (les deux copies relues) / réactiver (place vérifiée) / copie en lecture / suggestions                                                      | `archive.ts`                                                              | les boutons                     |

API : `GET /disk` (état, `?look=1`), `POST /disk/register|forget|update|eject|verify|repair`, `PATCH /disk`, `GET /disk/plan|trash|verify`, `POST /disk/trash/recover|erase`, `GET /files/:id/versions`, `POST /files/:id/versions/:vid/restore`, `POST /files/archive { ids | folderId }`, `POST /files/:id/reactivate|seen`, `POST /folders/:id/reactivate`, `GET /suggestions/archive`, `POST /restore/preview|apply`, `GET /files?state=pending|archived|suggest`.

Réglage : « Place réservée aux anciennes versions sur le disque (Go) », `historyQuotaGb`, 20 par défaut.

Pages : témoin du disque en haut des pages (`disk/DiskWitness.tsx`, « Mettre à jour »), point dans la barre latérale (`disk/DiskBadge.tsx`, `nav.badge`), plan / progression / compte rendu (`disk/UpdateDialog.tsx`), santé (`disk/Health.tsx`), vérification (`disk/VerifyDialog.tsx`), restauration (`disk/RestoreDialog.tsx`), versions dans l'aperçu (`disk/Versions.tsx`), corbeille du disque (`disk/DiskTrash.tsx`), réglages (`disk/DiskSettings.tsx`).
