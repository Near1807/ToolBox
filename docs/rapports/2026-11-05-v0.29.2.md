## Guide d'essai sur le S21 (à faire en premier)

### Télécharger l'APK

Les deux APK viennent du **même run** : https://github.com/Near1807/ToolBox/actions/runs/42089427877

- version 1 : https://github.com/Near1807/ToolBox/actions/runs/42089427877/artifacts/13443858075 (`toolbox-essai-opfs-v1-apk`)
- version 2 : https://github.com/Near1807/ToolBox/actions/runs/42089427877/artifacts/13445295664 (`toolbox-essai-opfs-v2-apk`)

Ils sont gardés jusqu'au 05/12/2026.

1. Connecte-toi à GitHub (le téléchargement d'un artefact l'exige). Le plus simple : depuis le navigateur du téléphone.
2. Ouvre le lien de la **version 1**. Si tu passes par le site : onglet **Actions**, à gauche « Android probe (essai OPFS) », run n° 3, section **Artifacts** en bas de la page.
3. Tu reçois un **.zip**. Ouvre-le avec **Mes fichiers** (Samsung) → **Extraire** : tu obtiens `toolbox-essai-opfs-v1.apk`.
4. Télécharge **aussi** la version 2 (elle servira à l'étape 6), mais ne l'installe pas encore.

> Garde bien les deux APK de **ce run-là**. Ils sont signés avec la même clé d'essai : la version 2 s'installe par-dessus la 1. Un APK d'un autre run aurait une autre clé, et Android refuserait la mise à jour.

### Installer (« Installer des applis inconnues »)

1. Touche `toolbox-essai-opfs-v1.apk` dans Mes fichiers.
2. Android répond « Pour votre sécurité, votre téléphone n'est pas autorisé à installer des applications inconnues provenant de cette source ». Touche **Paramètres**, active **Autoriser depuis cette source**, puis reviens en arrière.
3. Touche **Installer**. Si Play Protect avertit (appli inconnue), touche **Plus de détails** → **Installer quand même**.
4. L'appli s'appelle **ToolBox essai** (identifiant `be.toolbox.probe`, distinct de la future vraie appli).
5. Après l'essai, tu peux désactiver « Autoriser depuis cette source » (Paramètres › Applications › Mes fichiers › Installer des applis inconnues).

### Plus tard : la clé de signature de la vraie appli

Elle n'est pas utile pour l'appli d'essai, qui a sa clé d'essai. Elle servira à l'étape 3b.

> **Clé perdue = plus aucune mise à jour possible de l'appli sans la désinstaller (et perdre ses données sur le téléphone).**

1. **Choisis une phrase secrète** de 16 caractères au moins, et note-la dans ton gestionnaire de mots de passe.
   - Sur GitHub : **Settings** › **Secrets and variables** › **Actions** › **New repository secret**.
   - Nom exact : `KEYSTORE_EXPORT_PASSPHRASE` ; valeur : la phrase.
2. **Lance le workflow une seule fois.** « Android keystore (une seule fois) » (`.github/workflows/android-keystore.yml`) peut être déclenché de deux façons :
   - **à la main**, avec le bouton **Run workflow** de l'onglet Actions. Ce bouton n'apparaît que quand le fichier est sur `main` : il faut que tu aies fusionné `hub-v1` dans `main`, c'est ta décision ;
   - **par un tag** `android-keystore-1`, sans toucher `main`. Le plus simple : me demander, dans une session, de pousser ce tag. Sur GitHub, c'est aussi possible : Releases › Draft a new release › Choose a tag › `android-keystore-1` › Target : `hub-v1` › Publish.
3. **Télécharge l'archive.** Sur la page du run, section **Artifacts** : `toolbox-cle-android-chiffree`. Elle est gardée **1 jour** seulement.
4. **Ouvre** `toolbox-cle-android.7z` avec **7-Zip** et ta phrase secrète. Elle contient :
   - `toolbox-release.jks` (la clé) ;
   - `toolbox-release.jks.base64` ;
   - `LISEZ-MOI.txt` (mot de passe, alias, empreinte).
5. **Garde une copie de ces trois fichiers HORS de GitHub** : dans ton gestionnaire de mots de passe (pièce jointe) **et** sur une clé USB.
6. **Crée les 4 secrets GitHub** (noms exacts, valeurs dans `LISEZ-MOI.txt`) :
   - `ANDROID_KEYSTORE_BASE64` : tout le contenu de `toolbox-release.jks.base64` ;
   - `ANDROID_KEYSTORE_PASSWORD` : le mot de passe ;
   - `ANDROID_KEY_ALIAS` : `toolbox` ;
   - `ANDROID_KEY_PASSWORD` : le même mot de passe.
7. **Supprime l'artefact** : page du run › Artifacts › icône corbeille à côté de son nom.
8. **Ne relance pas le workflow** : une nouvelle clé remplacerait la première.

**Pourquoi chiffrée** : le dépôt `Near1807/ToolBox` est **public**. Ses artefacts sont téléchargeables, et ses journaux lisibles, par tout compte GitHub. Une clé en clair, même gardée un jour, pourrait être copiée. Le workflow n'écrit jamais la clé ni son mot de passe dans le journal (seule l'empreinte SHA-256, publique par nature, y apparaît). S'il ne trouve pas le secret `KEYSTORE_EXPORT_PASSPHRASE`, il s'arrête avec un message.

## 2. Ce qui a été fait

### Partie A — côté PC (`d106ec0`)

- **`modules/_template`** n'importe plus `node:fs`, `node:path` ni `@hub/sdk/backend`, seulement `@hub/sdk/core`. Son export de note passe par `ctx.files.outputPath(...)` et `ctx.files.writeFile(...)` (même chemin, même contenu ; son test passe sans changement).
- **Contrat** : `ctx.files.outputPath(...)` (chemin dans le dossier de sortie du module). `ctx.files.writeFile` accepte aussi le dossier de sortie du module (fichier généré), en plus de `dataDir` ; tout autre chemin est refusé.
- **ESLint** (`eslint.config.js`) :
  - tout module est **portable par défaut**, sauf ceux de `PC_ONLY_MODULES` (musique et assistant) ;
  - dans un module portable, hors tests, les globaux `Buffer`, `process`, `global`, `__dirname`, `__filename` et `require` sont refusés (`no-restricted-globals`), en plus des imports déjà refusés.
- **Tests** : `tests/portable-modules.test.ts` passe à 17 tests. Il prouve qu'un global de Node et un import interdit échouent dans les 5 modules, le modèle et un module nouveau. Rien n'est refusé dans les tests ni dans la musique et l'assistant, et les globaux Web (`crypto`, `btoa`, `TextEncoder`) restent permis.
- **Documentation** : `docs/MODULES.md` §4 et §5.2, `CLAUDE.md`.

## 4. Décisions prises sans Thomas

1. **Les deux versionCode dans le même run.** Un APK de debug est signé par la clé de debug du runner, différente à chaque run. Deux runs séparés donneraient deux clés, et la version 2 ne s'installerait pas sur la 1 : l'étape 6 échouerait sans rapport avec OPFS. Le paramètre `versionCode` reste, avec « 1 et 2 » par défaut. Pour changer : choisir « 1 » ou « 2 », mais alors désinstaller avant chaque essai.
2. **Déclencheur par push** de `android-probe.yml` (fichiers `mobile/probe/**` sur `hub-v1`) : seul moyen de le lancer sans `main`.
3. **Clé chiffrée par une phrase que tu choisis**, plutôt qu'un artefact en clair gardé un jour : le dépôt est public (§ « Pourquoi chiffrée »). La demande permettait « chiffré ou rétention d'un jour » ; j'ai fait les deux.
4. **Déclencheur par tag** `android-keystore-*` pour la clé, en plus du manuel : il permet de la lancer sans fusionner dans `main`.
5. **Modules portables par défaut** : la règle ESLint s'applique à tout module sauf la liste `PC_ONLY_MODULES` (musique, assistant), au lieu de la liste des 5. Le modèle et tout futur module sont donc couverts sans y penser. Pour changer : ajouter un module à `PC_ONLY_MODULES`, sur ta décision.
6. **`ctx.files.outputPath` et `writeFile` dans le dossier de sortie** : nécessaires pour que le modèle écrive son export sans `node:fs`.
7. **`setup-android`** avec `packages: platform-tools` : la valeur par défaut demande le paquet `tools`, qui n'existe plus (premier run en échec, §6). Gradle télécharge le reste.
8. **Versions épinglées** à des publications de plus de deux semaines quand c'était possible : Capacitor 8.5.3 (07/10) plutôt que 8.6.0 (28/10). sqlite-wasm 3.54.1-build1 est du 19/10.
9. **Clé de signature** : RSA 4096, validité 10 000 jours, nom `CN=ToolBox` (aucune donnée personnelle).

## 9. Risques et points à surveiller

- **Le pari OPFS** n'est pas encore vérifié sur le S21. S'il échoue, l'ADR prévoit le repli `sql.js` en mémoire, avec le fichier sauvegardé par le plugin Filesystem : à décider avec le rapport en main.
- **`storage.persist()`** : Chrome de bureau répond « non » sans interaction. Dans le WebView, la réponse dira si Android peut évincer OPFS quand la place manque.
- **Clé de debug de l'essai** : elle change à chaque run. Pour mettre à jour, il faut les deux APK du même run.
- **`setup-android@v3`** tourne sur Node 20, que GitHub déprécie (avertissement, pas d'erreur). À surveiller quand une v4 sortira.
- **Artefacts publics** : les APK d'essai sont téléchargeables par tout compte GitHub. Ils ne contiennent aucune donnée personnelle.
